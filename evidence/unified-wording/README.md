# All-module wording evidence

All data in this directory concern the user's explicitly synthetic, 112-position test table.

- `captured-*.json`: unchanged real Groq response content, using temporary tooth aliases. No credentials, patient notes or original tooth identifiers.
- `approved-*.json` / `.txt`: complete reports generated by replaying those captures through current validation and the report service. No provider call during replay.
- `approved-summary.json`: capture hashes, all 16 accepted comments per module, 112 positions, 96 rules, and distinct opening counts.
- `provider-verification.json`: distinguishes live acceptance from offline revalidation. Nano's final captured response was initially rejected for neutral grammar and accepted after correcting that validator vocabulary; no claim of a subsequent live success.
- `finova-*-ai-comments.pdf`: actual browser exports of the approved reports. The displayed comments match the UI, with complete original TXT/JSON attachments.
- `pdf-verification.json` and `visible-*.txt`: extraction and attachment verification of those PDFs. Visual review covered all 16 pages (Macro 4, Micro 6, Nano 6).
- `visual-review/`: PDF contact sheets plus inspected desktop/mobile UI crops. `verification-summary.json` records the final test outcomes and the six corrected browser-test reruns.

Reproduce report acceptance from the project root:

```powershell
.\backend\.venv\Scripts\python.exe backend/scripts/verify_interactive_wording_replay.py
```

The browser suite uses these captured reports for the approved UI/PDF cases, and a real local backend with the key disabled for deterministic fallback cases. Browser regression is not an additional live-provider or clinical validation claim.
